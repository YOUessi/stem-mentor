## 检索已经做到了什么

`backend/app/retrieval.py` 对26条真实文档建立 SQLite FTS5 + BM25 检索，中文使用简易二元分词，并结合人工结构标签和条件禁用规则过滤。它**不是语义完整的向量 RAG**，也不具备对未标注任意新题的可靠数学方法判别能力。

当前学生真实解题记录存于本地 SQLite，不应混入公用的教材/方法语料。历史题目回忆只能引用该模拟学生**目标会话创建之前**已记录完成、结构标签足够接近的练习；不意味着旧题做对或本题迁移成功。

## 最大的知识内容缺口

目前26条方法卡都具备先修知识、适用边界和启发文字，但都**没有独立结构化的定理完整陈述/证明、完整受控例题、反例和常见误区字段**。113条课程工程记录也未形成完整的知识讲义。

下一阶段不能只继续增加图形场景数量，需要建立：

1. **知识原子**：概念与定义、符号/单位、定理原文、全部假设、结论、等价与必要/充分关系。
2. **严格证明与使用说明**：逐步数学推导、条件验证、反例、边界和退化情况；明确哪些步骤可被符号验证。
3. **题型与方法卡**：触发结构、适用理由、何时不能使用、替代方法、正推/逆推/桥梁、近远迁移关系。
4. **多层提示**：先引导观察和尝试，再最小启发，再验证约束；完整解法仅教师审核层可见。
5. **知识来源与审核**：许可、原始出处、课标版本、适用年级、编辑者、审核者、审查日期、版本历史。未经审核显示 `PENDING`。
6. **可重复知识测验**：典型例题、错误解法、反例、无提示变式、延迟复习与按条件正确性评分。
