# 历次需求讨论与设计决定（整理记录）

> 本文件依照本项目当前对话中的实际表述整理，**不是逐字完整聊天备份**；不虚构缺失消息/时间戳。仅保留与产品研发有关的观点，不上传账号密钥、其他项目路径或个人隐私。记录截至 2026-10-15。

## D01 教育 Agent 的基本主张
原始需求：“理科的，个人的教育agent…llm学习到一些好的思路，以及一些开放型的启发，举一反三…教材基础知识rag，重难点题型rag，各种模型方法rag。”
决定：设计长期学生私人培优教师；知识分教材、题型、模型方法、通用思维、教学策略、个人真实经历。专项方法举例有解三角形中的阿波罗尼斯圆、圆锥曲线切线的换一半法则。方法卡记录适用条件、证明、反例和迁移边界。

## D02 不直接把答案给学生
原始诉求：“回答疑问的过程也不是直接将答案，而是一步一步去激发学生的思维，像一个真正的培优老师一样。”
决定：默认最少必要提示，让学生自行尝试；允许必要时讲解，不以机械提问代替教学。

## D03 基础但考试要考的细节
补充：“一些细微的不重要不难的知识点，但是升学考试（中考高考）要考察的，也需要时不时提醒学生。”
决定：建立考试微考点库；配合复习调度、情境相关性、个体易错记录、提醒限频；考试范围须有来源、地区和年份，不以 LLM 口述作为依据。

## D04 关联个人过去的实际解题经历
补充：“后面的一个问题的方法技巧和之前的一个题目很像，也要引导学生去回忆之前是怎么做的…迁移运用。”
决定：保存学生真实解题过程、原始草稿、方法、卡点、提示、突破和独立表现；优先结构/方法相似而非文本词语相似；没有真实旧题不得虚构回忆。

## D05 高价值是突破口而不是线性全解
补充：“给学生的需要的更多是思路，不是完整的答案…从头开始几步，然后会卡住，然后就会从问题入手，反推，然后由正推，到最后一步的数据处理或者化简的时候，一般都是一些固定的方法。”
决定：把正推、逆推、卡点、桥梁、常规运算分开，教授策略切换的原因；默认不全解，常规计算交回学生。记录非线性探索路径；逆向得到的条件要区分充分/必要。

## D06 模式的明确区分
补充：“推理模式，就是一步一步引导，一个是逻辑模式…首先引导学生分析题目本质，问题，条件，有什么方法。”
决定：逻辑分析 ANALYZE 专注审题与方法选择；推理陪练 GUIDE 专注已有思路与动态推进；再增加自主挑战 INDEPENDENT 用于无提示能力检验。模式可切换且共享底座，辅助回忆/微考点/数学检查不是每次都要切成新模式。

## D07 进一步建议并已纳入设计
- 解题思维地图：已知、目标、正推关系、反推子目标和关键桥梁；标记猜想与可验证结论。
- 方法对比与反例训练：不仅知道如何套，还要知道何时不能套。
- 教学渐退：逐步从充分启发转向轻提示、无提示迁移。
- 解题后复盘：学生解释关键转折，避免自动播放答案。
- 教回去：完成后可让学生解释方法动机，但不强制每题反思。

## D08 工程与科研
先做 Web 工作台、共享教学状态机、结构化数学知识与学生记忆，不一开始训练模型。评测区别数学正确率、提示质量、独立解题、远近迁移、延迟保留、避免误提示。正向/反向策略切换与历史经验迁移是重点实验变量。
